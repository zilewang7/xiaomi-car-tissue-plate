# 纸巾盒旋转挪车号码牌

**English summary.** A 3D-printed rotating triangular-prism parking plate (挪车号码牌) for the XIAOMI LIFE magnetic
tissue box in Xiaomi cars. It sits along the front edge of the tissue-box lid, readable from outside through the
windshield, and shows face A, face B (each a phone number or one line of your own text) or face L (a YU7 side
sketch with "YU7 PRO", your own wordmark, or text only); a ∇ knob with magnetic detents turns it to the next face
with a click. Everything is generated by Python (build123d): the parts, automatic checks, one Bambu Studio 3MF with
two plates (sliced by the Bambu Studio CLI), renders and a Chinese assembly card. A local web UI (127.0.0.1 only)
edits the config, previews the faces and runs the build; it and the command line run on macOS, Windows and Linux
(tested with the example numbers on macOS, Windows 11 and Ubuntu 24.04 under WSL2).
Your numbers and texts stay in a local, git-ignored `config.toml`. The print settings target a Bambu Lab P1S with
AMS and Bambu ABS. Verified only in the author's YU7. The documentation is in Chinese. Not affiliated with Xiaomi
(see the disclaimer below).

![车外俯视 35°，示例号码（v3.1 时的渲染）](concept/renders/v3.1_render_outside_35deg.png)

## 这是什么

- 一根约 20 cm 长的藏青三棱柱，横在纸巾盒上盖靠前挡的那条边上，从车外透过前挡风玻璃读。三个面：
  - **A 面、B 面**：白字的手机号（按 3-4-4 分组），或者一行自己的文字（§自定义文字）；
  - **L 面**：默认是 YU7 车身侧影加「YU7 PRO」；可以换成自己的一行字，也可以去掉侧影只放文字。
- 主驾一侧有个 ∇ 旋钮，里面是磁铁档位。竖直往下按靠座舱的那个角，"咔"一声换到下一面（A → B → L）；按靠前挡的
  角回到上一面。不用看，摸旋钮顶边就知道哪一面朝外：1 条棱是 A，2 条棱是 B，宽棱是 L。
- 两片挂片吸在纸巾盒本身的磁点上，每片 4 颗磁铁：下面 2 颗吸底座的磁点，上面 2 颗吸上盖的磁铁。托架的唇板用
  1.2 mm 的 3M VHB 双面胶粘在上盖顶上；补纸时连牌带盖一起竖直掀开。
- 尺寸、检查、出图都由 Python 生成。`scripts/build_all.py` 一条命令依次完成：建模 → 几何验证 → 导出 STL / STEP →
  自动检查 ①–⑪ → 生成一个两盘的 Bambu 3MF，并用 Bambu Studio 命令行切片 → 渲染图 → 中文装配卡 → `out/report.md`。
  自动检查覆盖：字形和排版、转动扫掠和干涉、装配和补纸的路径、车外可见性、磁力、80 ℃ 且盒内磁铁按最弱估算时的
  静力（离地、刹车）、可打印性（孔壁厚度、横孔泪滴形）、档位力矩下托架的抬起，以及逐盘切片结果。

## 适用车型

- **盒子**：小米官方的 XIAOMI LIFE 车载磁吸纸巾盒，铭牌型号 O636。不改车，也不改盒。
- **车型**：
  - YU7：盒子直接放在前挡下的凹槽里，就是作者装车的那一套；
  - SU7：先装"小米汽车磁吸适配托盘"，纸巾盒吸在托盘上。小米商城的商品页写明托盘适用于第一代 SU7、第二代 SU7、
    SU7 Ultra。
- **验证范围**：只在作者的 YU7 里装车验证过。盒子的尺寸和磁点是在作者的盒子上量的；车里的空间、视线和温度是在
  YU7 里量的，除了 `tab_bottom`，都不能在配置里改。
- **SU7 车主打正式件之前，先在车里查三项**（盒子在托盘上的位置和 YU7 不同，没测过）：
  - **位置和视线**：盒子平放在前挡下面，站在车头前 0.5–2 m 斜着往下看，能看到盖顶往上 15–37 mm 那一段。坐在
    主驾，伸手能按到盒子靠主驾的那一端，旋钮在这一端。
  - **空间**：
    - 两个底座磁点处，盒面前方要有 ≥ 8 mm 空隙，从盖顶一直往下到 40 mm；
    - 整条横梁比盒子两端各长约 10 mm，它的前方在盖顶下 9 mm 以内也要有 8 mm；
    - 两端在盖顶以上要空出约 10 mm（远端；贴了外挡时约 12 mm）和 18 mm（旋钮端）；
    - 补纸时连牌带盖竖直提起，上方要空出约 8 cm。
  - **不影响开车**：不挡视线、不挡仪表和 HUD；盒子不在安全气囊展开的位置。
- **最省事的查法**：视线和开车两项，剪一条 200 × 37 mm 的硬纸板，立在盖顶前沿看；空间那项，拿一块 8 mm 厚的
  东西，贴着盒面往下滑到盖顶下 40 mm。
- **温度**：YU7 前挡下的凹槽夏天实测 66–76 ℃（转引，不是作者自己量的）；官方说可能超过 90 ℃。设计按 80 ℃ 校核、
  90 ℃ 复核，别的车型没有数据。

## 需要什么

**软件**

- macOS、Windows、Linux 都能用。Windows、Linux 下载仓库之前先看 §三个平台：Windows 的仓库要放在用户目录下；Linux
  要先装几个系统包，要出 3MF 的话再解开 Bambu Studio 的 AppImage。
- Bambu Studio，可选。构建会调用它的命令行切片，并读取它自带的拓竹系统预设（`Bambu Lab P1S 0.4 nozzle`、
  `0.20mm Standard @BBL X1C`、`Bambu ABS @BBL P1S 0.4 nozzle`）。作者用的是 02.08.02.61，预设名按这个版本写，
  别的版本在网页顶栏会标"版本不同"。各平台去哪里找它见 §三个平台。
  - 没有能用的 Bambu Studio（没装、找不到这三个预设，或者起不来）时，构建走不切片模式：照常出检查、渲染图、
    报告和装配卡，只是不出 3MF，退出码 3。装配卡 §1 末尾列出每件要在切片软件里手动设的项：三个预设、AMS 槽，
    每件的墙数、填充和 brim，陪打柱 Q 的 20 mm/s。
- [uv](https://docs.astral.sh/uv/getting-started/installation/)（官网一条命令；macOS 也可以用 Homebrew，Windows
  也可以用 winget）：网页的启动脚本和 §构建 第 1 步都用它建 Python 3.12 的环境，不用另装 Python（本机没有 3.12 时
  uv 会自己下载一份）。不用 uv、自己建环境的话，Python 3.12–3.14 都行。
- git：推荐用 `git clone` 下载仓库（没装过 Xcode 命令行工具的 Mac，第一次运行 git 会先弹窗要求安装；Windows
  要先装 Git）。用 zip 下载也行，第一次启动可能被系统拦下（§网页界面）。
- 字体 MiSans Bold：许可协议不允许单独分发字体文件，但允许分发用它做出的作品，并要求注明用了 MiSans。所以仓库里
  没有字体，要自己下载（见下）。

**打印**

- 拓竹 P1S（0.4 喷嘴）+ AMS，三个槽：**1 号白、2 号天蓝、3 号藏青**。生成的 3MF 和切片设置都是按 P1S 做的，别的
  机型没试过。
- 拓竹 ABS 三色：白 40100、天蓝 40601、藏青 40602（打印前先烘干）。纹理 PEI 板，涂胶。

**外购件**（默认配置；准确的清单和数量以构建生成的装配卡 §2 为准）

- N52 Ø8×3 mm 钕磁铁 15 颗：挂片 8、旋钮 6、定子 1。
- M3×25 盘头自攻螺钉 1 颗。
- 3M VHB 双面胶，1.2 mm 厚（作者用的是 20 mm 宽的卷），剪两条。
- 5 分钟 AB 胶（标 100 ℃ 的那种）；另备一支慢干 AB 胶（什么时候用见装配卡）。
- 其余辅料和工具见装配卡。

## 网页界面

不想手改 `config.toml`、不想敲命令的话，用本机网页：填写、看三面预览、构建、打开 3MF，都在浏览器里点。
页面背后跑的还是 `scripts/build_all.py`。

1. **准备**：照 §需要什么 装好 uv、下载仓库；字体照 §构建 第 2 步放进 `fonts/`，缺字体时页面也会提示。Linux 先照
   §三个平台 装好系统包（要出 3MF 的话再解开 AppImage）。
2. **启动**：macOS 双击仓库里的 `start-webui.command`；Windows 双击 `start-webui.cmd`；Linux
   在终端里运行 `./start-webui.sh`。后面加的参数原样传给 `scripts/webui.py`（见下面的"命令行"）。
   - 第一次启动会用 uv 按 `requirements.lock` 建 `.venv`，要联网下载约 280–390 MiB 的依赖，环境占 0.9–1.5 GB。
     在作者的 Mac 上约 2 分钟，网慢时要久得多（测试用的一台 Windows 电脑下了 42 分钟）。建好以后，构建程序第一次
     加载要几秒到 1–2 分钟（§常见问题）；以后几秒就能打开。
   - `.venv` 和 `requirements.lock` 对不上时（比如 `git pull` 改了锁文件，或者上次没装完），启动脚本会照它重装。
   - 没装 uv 时，脚本只打印 uv 的安装页面，然后停下。
   - 用 zip 下载的，第一次可能被系统拦下（`git clone` 的没有这一步）：
     - macOS：到「系统设置 → 隐私与安全性」点「仍要打开」（macOS 15 起右键 → 打开不管用了），
       或者在终端里执行 `xattr -d com.apple.quarantine start-webui.command`。没实测。
     - Windows：弹"安全警告"或 SmartScreen 时，确认是这个仓库里的文件再点"运行"；
       也可以解压前在 zip 的属性里勾选"解除锁定"。没实测。
3. **打开页面**：浏览器会自动打开 `http://127.0.0.1:<端口>/#token=…`。
   没打开时（比如在 WSL 里），把终端里打印的这条链接复制到浏览器。
4. **在页面上**：
   - 「从 config.toml 读取」（有这个文件才能点）、「保存到 config.toml」：打开页面时不自动读，
     免得共享屏幕时露出号码。保存时写全所有键（以后默认值变了，零件也不会跟着变），手写的注释会换成模板注释。
     保存前，原文件另存为 `config.toml.orig.bak`（只在第一次保存时写）和 `config.toml.<时间>.bak`（只留最近 5 份）。
   - 「导入…」「导出…」另一份 TOML；三面预览随输入刷新，打不出来的字标出是第几个。
   - 「开始构建」：约 2.5–3.5 分钟（不跑 v3.1 比对），同一时间只跑一个，可以取消。产物在 `out/web/<任务>/`，
     只留最近 5 次，每次约 74 MB。
   - 构建完：「用 Bambu Studio 打开」3MF，或者「在访达中显示」（Windows 是「在资源管理器中显示」，Linux 是
     「打开所在文件夹」），都不复制文件；装配卡、报告和渲染图在页面里看。下载单个文件、打包成 zip，
     只在要拷到别的电脑时用。
5. **停止**：在终端里按 Ctrl+C、关掉终端窗口（Windows 是那个命令行窗口），或者点页面顶栏的「停止」；
   正在跑的构建也会一起停。

**命令行**：`.venv/bin/python -I -X utf8 -u scripts/webui.py`（Windows 是 `.venv\Scripts\python.exe`，
参数相同）。`--port N` 固定端口（默认每次挑一个空闲的），`--keep N` 保留几次构建（默认 5），`--no-browser`
只打印链接、不开浏览器，`--example` 只用示例配置、从不读写 `config.toml`（截图、演示用）。

**隐私**

- 服务器只绑 127.0.0.1，同一局域网的其他设备连不上；每次启动换一个新令牌，只有终端里打印的那条链接能用。
  页面不联网，号码和文字不出这台电脑。
- 但「导出…」的 TOML、下载的文件和 zip 会在浏览器的下载文件夹里多一份带号码的副本，用完删掉。
- 打印只用"仅局域网（LAN only）"模式或 SD 卡：云模式下文件先传到拓竹云，默认保存 90 天，Bambu Handy
  的打印记录里还有带号码的缩略图。不要传 MakerWorld（§打印）。

## 三个平台

命令行和网页在三个平台上是同一套代码，差别在启动方式和去哪里找 Bambu Studio：

| 平台 | 启动网页 | 默认去哪里找 Bambu Studio |
|---|---|---|
| macOS | 双击 `start-webui.command` | `/Applications/BambuStudio.app`，再找 `~/Applications/BambuStudio.app` |
| Windows | 双击 `start-webui.cmd` | `%ProgramFiles%\Bambu Studio\bambu-studio.exe` |
| Linux | 在终端里运行 `./start-webui.sh` | 没有默认位置：用环境变量指到解开的 AppImage 里的 `squashfs-root/AppRun`（见下） |

- **找 Bambu Studio**：设了环境变量 `TISSUEPLATE_BAMBU_STUDIO`（可执行文件）就只用它，路径不对时按没找到处理，
  不再去默认位置找；`TISSUEPLATE_BAMBU_PROFILES` 指它的 `profiles/BBL`，一般不用设。找到以后先试跑一次，起不来
  （比如 Linux 缺系统库）也算没有，走不切片模式。
- **Windows**：仓库放在自己的用户目录下，路径尽量短（Windows 默认没开长路径支持）。
  Windows 上 0600 / 0700 不起作用，号码文件的私密靠用户目录继承下来的权限；放在别处
  （比如 D 盘根目录）时，同一台电脑的其他用户可能读到 `config.toml` 和 `out/`，页面会提醒。
  也别放进 OneDrive 同步的「桌面」「文档」（§隐私）。
- **Linux**：
  - 系统包（Debian / Ubuntu 的包名；桌面版一般已经有前两组）：

    ```bash
    sudo apt install libgl1 libx11-6                                      # 构建
    sudo apt install libegl1 libgl1-mesa-dri                              # 离屏渲染
    sudo apt install libwebkit2gtk-4.1-0 libgstreamer-plugins-base1.0-0   # 切片（Ubuntu 24.04 版 AppImage）
    ```

    三组都装上以后，WSL2 里的 Ubuntu 24.04 能切片：克重、换色次数和 Mac 相同，时间差不到 1 min。
  - Bambu 只出了 Ubuntu 22.04、24.04 两版 AppImage。Ubuntu 20.04 没有 `libwebkit2gtk-4.1`，切不了片，
    只能走不切片模式。
  - 解开 AppImage（不需要 FUSE），再把 `TISSUEPLATE_BAMBU_STUDIO` 设成解出来的 `squashfs-root/AppRun`
    的完整路径（profiles 在它旁边，不用另设）。AppImage 先放到仓库外面的目录里（比如 `~/Applications`）再解开：
    `squashfs-root/` 很大，又不在 `.gitignore` 里。

    ```bash
    cd <放 AppImage 的目录>                      # 在仓库外面，比如 ~/Applications
    chmod +x <AppImage 文件名>
    ./<AppImage 文件名> --appimage-extract       # 在当前目录解出 squashfs-root/
    export TISSUEPLATE_BAMBU_STUDIO=<放 AppImage 的目录>/squashfs-root/AppRun
    cd <仓库目录> && ./start-webui.sh            # 命令行构建也认这个变量
    ```

    `export` 只对当前这个终端有效：以后每次新开终端，都要先 `export` 一次再启动网页或构建；也可以把 `export`
    这一行写进 `~/.profile`（重新登录以后每个终端都有）。没设时网页顶栏写"没有能用的 Bambu Studio"，
    构建走不切片模式。

- **渲染**：没有 OpenGL 3.2 的电脑（虚拟机、部分远程桌面）上渲染可能失败。
  这时构建照常往下走，只是没有渲染图，报告和装配卡里写明"这台电脑没出渲染图"和原因，
  页面上也会提示。Linux 上没有显示时自动走 EGL，读不了显卡时用软件渲染，构建日志里会多几行
  `libEGL warning`，图照样出。

**测到了哪一步**（10-20 – 10-21，只用示例配置）：Windows 和 Linux 都在作者的一台 Windows 11 电脑上测，Linux 是它的
WSL2 Ubuntu 24.04。10-21 用发布的这一版重跑了三处的测试套件、Windows 和 WSL 的网页构建与取消（含切片当中）、Mac 上

## 构建

1. 建虚拟环境、装依赖（按锁文件装，版本和哈希都和作者的一样；网页的启动脚本第一次运行时会自动做这一步）：

   ```bash
   uv venv --python 3.12 .venv
   uv pip install --require-hashes -r requirements.lock
   ```

   Windows 上 `uv venv` 报 os error 448 时见 §常见问题。

2. 字体：从小米官方页面 <https://hyperos.mi.com/font/download> 下载 MiSans，把 `MiSans-Bold.ttf` 放进 `fonts/`，
   文件名不要改。只需要这一个文件。
   - 作者用的是 MiSans 4.009，sha256 `d0c1d327952ed935e86fb78a97a6c182b44f2c2b08777326786b1f8b26d1fe1e`。
   - 你下到的版本不同也能构建：构建时会提示一行，报告里记一行"字体和作者的不同，排版可能略有差别"，
     `scripts/wordmark_check.py` 会跳过并说明原因。

3. 配置：

   ```bash
   cp config.example.toml config.toml
   ```

   Windows 的命令提示符里把 `cp` 换成 `copy`。在 `config.toml` 里填你的内容：
   - `[numbers]` 的 `a` 是 A 面，`b` 是 B 面，都是带引号的 11 位数字、以 1 开头；
   - 想在某一面印文字，就把它从 `[numbers]` 里删掉，写进 `[text]`（§自定义文字）。

   其余键都可以不写，不写就用默认值；每个键的含义见 `config.example.toml` 里的注释，允许范围以
   `src/tissueplate/config.py` 为准。写错了构建会停下来报错，不会自动修正，报错里也不回显你填的值。

   `[mount]` 的 `pad_t`、`delta_up`、`tab_bottom` 三个值要一起改（示例里给了两组）。只改一个，前横梁 F 会悄悄变，
   装配卡 §1-1 会出一行"注意"。

4. 构建：

   ```bash
   .venv/bin/python -I -X utf8 scripts/build_all.py
   ```

   Windows 上把本文命令里的 `.venv/bin/python` 都换成 `.venv\Scripts\python.exe`，参数不变；`-X utf8`
   让系统代码页不是 UTF-8 的 Windows 也按 UTF-8 读写。

   - `--config FILE`：换一个配置文件，比如先用 `--config config.example.toml` 拿示例号码试跑；
   - `--no-v31`：跳过和 v3.1 参考脚本的几何比对；
   - `--geometry-only`：只建模、验证、导出 STL / STEP；
   - `--no-slicer`：不用 Bambu Studio，不出 3MF、不做切片检查。没找到或起不来 Bambu Studio 时会自动这样。

   每进入一步打印一行 `[stage i/7] <名字>`，一共 7 步，网页的进度就按它显示。退出码：

   - 0：成功（最后打印 `all done`）；
   - 1：几何验证、硬性检查或切片检查没通过，或者没写出 `out/report.md`；
   - 2：配置错误（文字排不下、打不出来也算）；
   - 3：没切片就结束：没有能用的 Bambu Studio，或者用了 `--no-slicer`。检查、渲染图、报告和装配卡照出，
     只是没有 3MF；
   - 4：内部错误：终端只打印错误类型和出错位置（文件:行），完整的 traceback 写进输出目录的 `build_error.log`。
     它可能带你填的值，只在本机看。

   在作者的 Mac 上完整构建约 4 分钟。

5. 输出都在 `out/`（网页的每次构建在 `out/web/<任务>/`，里面的结构一样）。环境变量 `TISSUEPLATE_OUT_DIR`
   可以换一个文件夹，但要放在仓库外面：仓库里只有 `out/` 被 `.gitignore` 忽略。

   | 路径 | 内容 |
   |---|---|
   | `out/plates/parking_plate.3mf` | 一个文件两盘（盘 1 彩色、盘 2 藏青），耗材分配、每件的打印设置都已带好；不切片模式下没有 |
   | `out/plates/slice_report.json`、`out/plates/slice/` | 命令行切片的结果（时间、克重、换色次数）和 G-code |
   | `out/parts/` | STL / STEP（打印姿态和装配姿态）、`geometry_report.json` |
   | `out/checks/checks_report.json` | 自动检查明细 |
   | `out/renders/` | 渲染图（含号码和文字） |
   | `out/<YYYY-MMDD-HHMM>-装配卡.md` | 中文装配卡：打印、准备、试配、装配、自检、使用的全部步骤 |
   | `out/report.md` | 构建报告：检查结论、配合、每盘切片结果、交付文件 |

   不切片模式下也没有 `out/plates/slice/`；`slice_report.json` 里只有手动设置用的每件清单
   （预设、AMS 槽和每件设置，没有时间、克重和换色次数），报告里的切片结果写"未切片"。

   装配卡是照作者自己的制作过程写的，车内的步骤写的是"作者的 YU7 里……"。

## 自定义文字

```toml
[numbers]
a = "13800138000"          # A 面照旧是号码

[text]
b = "MOVE MY CAR? CALL"    # B 面换成一行文字（并从 [numbers] 里删掉 b）
l = "YU7 MAX"              # L 面：替换侧影旁边的「YU7 PRO」

[display]
logo = "final"             # "none"：去掉侧影，L 面只放 [text] l 这一行字
```

- **SU7 车主**：建议 `[display] logo = "none"`，L 面只放文字，因为侧影画的是 YU7（页面上也这样建议）。
- **每面一处**：A、B 两面各在 `[numbers]` 或 `[text]` 里恰好写一次；`l` 可选，只能写在 `[text]` 里。
  `logo = "none"` 时必须写 `l`。不写 `l` 时 L 面和以前完全一样。
- **一行字，自动排版**：A、B 面（和只放文字的 L 面）选这一面放得下的最大字号，太长时先把字横向压窄（最多到
  0.86），再缩小字号；字号 × 压缩小于 8 mm 就报"太长"。L 面侧影旁边的字从今天的 9.03 mm 起往小试，最小 8 mm，
  离图案至少 1.5 mm，放不下就报错。
- **大陆手机号继续写在 `[numbers]`**：写进 `[text]` 会按字体字距排，没有 3-4-4 分组，打出来不一样。
- **提前报错**：字体里没有的字、太长、按盘 0 的下限打不出来（字怀糊死、L 面侧影旁边的笔画会断）、CAD 切不出
  封闭实体，都会在构建开头停下，说明是第几个字、什么原因，退出码 2。报错和报告里只写位置，不写文字本身。
- **中文**：建议 L 面用 `logo = "none"` 只放文字（侧影旁边只有 9 mm 左右，多数带"口、日、目"的字字怀会糊死）。
  A、B 面满高时一行约 8–9 个字。
- **没试打过的**：字内窄缝（< 0.5 mm）和 A、B 面的断笔只报警告，判法没有试打验证过；压窄的中文也没打过。打出来
  笔画不清楚，就换个字或者改成只放文字，再重打那一面。面板粘进管以后，换哪一面都是整管重打。

## 打出来不合适时

不用先打试件：直接按默认值打整套。默认值是作者在 P1S 上用盘 0 / 0b 选出来的。装配卡在粘之前逐个试配（主要在
第 3 节），每一步都写了不合格怎么办，汇总如下：

| 哪里不合适（装配卡） | 先试 | 再改哪个键 | 只重打 |
|---|---|---|---|
| K 的圆轴在 C 的近端孔里转不开（§3-1） | 手拧 Ø6.0 钻头铰孔（§3-2） | `[fit] near_hole` 加 0.05 | C |
| P 的圆轴在 C 的远端孔里转不开（§3-5） | 同上 | `far_hole` 加 0.05 | C |
| K 的六角推不进 EN（§3-3） | — | `hex_socket_af` 加 0.05 | EN |
| K 插进 EN 后明显晃（§3-3） | — | `hex_af` 加 0.05 | K |
| P 的六角推不进 EF（§3-4） | — | `far_hex_af` 减 0.05 | P |
| P 插进 EF 后会自己掉（§3-4） | — | 贴外挡（装配卡 §3-4） | — |
| 盖片按不进（§8；轴盖在 §11-3） | — | `tab_cap_d`、`knob_cap_d`、`hub_cap_d` 减 0.05 | 那一组盖片 |
| 盖片偏松 | 照 §11 点胶粘牢 | 不改键：默认已经是允许的最大值，轴盖再大会碰沉孔 | — |
| M3 头太高，轴盖压不平（§11-3） | 量一下螺钉头高 | `[hardware] screw_head_k` 改成量到的值 | K |

- **在切片软件里缩放**：把要重打的那一件在切片软件里缩放一点再打也行，但缩放会带上整件的所有尺寸：
  - 盖片：只有外径这一处配合，缩放没有副作用；
  - P：缩小 1 % 时六角小约 0.05，轴颈也小约 0.06，远端会更松、更容易"嗒"。能用，但不如改 `far_hex_af`；
  - C、K、EN 不要缩放：C 的长度和孔位、K 的轴颈和磁铁孔、EN 塞进管里的外形都会跟着变。用上表的键。
- **怎么只打一件**：改完键重新构建，在 Bambu Studio 里打开新的 `out/plates/parking_plate.3mf`（网页上点
  「用 Bambu Studio 打开」），按装配卡 §1-5 做：要打的件都放到盘 1，和陪打柱 Q 一起打（小件 K、EN、EF、P、D、S
  不能单独打），盘 1 上不打的件删掉，只切片、打印这一盘。这些试配都在粘之前做，所以只重打那一件。

## 打印

- 用 Bambu Studio 打开 `out/plates/parking_plate.3mf`（网页上点「用 Bambu Studio 打开」），逐盘切片、打印。
  细节见装配卡 §1。不切片模式下没有 3MF：照装配卡 §1 末尾的「手动设置」自己建两盘，或者装好 Bambu Studio
  再构建一次。
- **只用两种方式发送**：打印机的"仅局域网（LAN only）"模式，或者 SD 卡。打印机绑定账号、用默认的"自动 / 云"模式
  时，发送打印会先把文件传到拓竹云，默认保存 90 天；Bambu Handy 的打印记录里还会有带号码的缩略图。一定要用云的
  话，在 Bambu Handy 的"设置 → 隐私设置"里打开 Incognito Printing（它只是少存打印记录，文件照样经过拓竹云），
  打完到打印记录里删掉这一条。不要传 MakerWorld。
- **关掉「延时摄影」**：局域网打印时在发送对话框里不勾选；用 SD 卡时，打印机屏幕上开始打印的选项里有这一项也关掉。
  开着的话每层都会停下来拍照，停的地方会留疙瘩。
- **小件不要单独打**：盘 1 上的 Q 是"陪打柱"，切片时别删，打完扔掉。同一高度上只有一件小件在打时，每层只有
  2–3 s，ABS 容易过热打胖；作者 10-16 打的那只旋钮卡死在近端塞里，很可能就是这个原因。
- 关门、盖顶盖，开打前预热 10–15 min；全程不暂停，磁铁等打完再装。

  `config.toml.<时间>.bak`），`out/`（网页的构建在 `out/web/<任务>/`，每个任务里还有一份这次的 `config.toml`），

  这些文件它另外列出来，要你自己一张张看过（或者干脆不公开）。

## 常见问题

- **第一次运行后，用户目录里多了几个缓存文件夹**：是 matplotlib、ezdxf 的字体缓存（Linux 上还有 Mesa
  的着色器缓存），还有 uv 的下载缓存（`uv cache clean` 可以清掉）；本机没有 Python 3.12 时，uv 还会
  自己装一份（`.venv` 要用它，别删）。这些里面都没有号码。ezdxf 建字体缓存时，终端里可能有一两行
  `cannot open font …`（系统里有它读不了的字体），不用管。
- **页面写"正在加载构建程序"**：新建 `.venv` 以后第一次启动，构建程序（主要是建模库）要加载
  几秒到 1–2 分钟，慢的电脑更久；以后几秒。
  终端里先打出"正在后台加载构建程序"，加载完打出"构建程序已加载（N s），页面可以用了"，页面会自己继续，
  不用刷新。浏览器等不了这么久时，页面改写"连不上服务器"：等终端打出那一行，再刷新页面。
- **页面写"服务器没准备好"**：构建程序没加载起来，原因在终端里"加载构建程序失败："那一行。Linux 上常见的原因
  是缺系统包：照 §三个平台 装好以后，在终端里按 Ctrl+C 停掉服务器，再运行一次 `./start-webui.sh`。
  终端里没有这一行、也还没打出"构建程序已加载"的话，是还在加载（服务器最多让页面等 10 分钟）：等它打出来再刷新页面。
- **打出来某一件不合适**：不用整套重打。照 §打出来不合适时 改那一件的键（网页里多数在「配合（不合适时改）」
  一组，M3 头高在「五金」），只重打那一件。
- **没装或用不了 Bambu Studio**（网页顶栏写"没有能用的 Bambu Studio：不出 3MF"，鼠标停在上面显示原因）：
  照样能构建，走不切片模式（§需要什么）：没有 3MF，页面显示「完成（没切片）」，命令行退出码 3。装好以后
  重启网页、重新构建，就会出带好全部设置的 3MF。
- **用 Bambu Studio 打开过 3MF 以后，临时目录里多了 `bamboo_model`**：是 Bambu Studio 图形界面防崩溃的项目备份。
  它开着的时候，备份里有模型，也就是有号码；正常退出时它删掉模型，只留一个小文件夹（作者的 Mac 上是
  `_temp_3.config`、`lock.txt`、`origin.txt`）；崩溃或被强制退出时整份备份都留着，下次启动它会问要不要恢复。
  关掉 Bambu Studio 以后可以整个删掉：macOS 在 `$TMPDIR/bamboo_model`，
  Windows 在 `%TEMP%\bamboo_model`。构建时的命令行切片不留这些。
- **页面写"访问令牌缺失或已失效"，或者只显示 403**：用终端里打印的那条完整链接打开（带 `#token=…`），
  别手敲地址，也别用旧书签。每次启动都换一个新令牌，端口也会换（除非用了 `--port`）。
- **Windows 上 `uv venv` 报 os error 448**（在一台 Windows 11 上见过；同一台电脑上，uv 新装到另一个目录的
  Python 3.12 没有这个问题）：uv 管理的 Python 用了目录联接，这台电脑不信任它。`start-webui.cmd` 遇到时会改用标准库 venv
  建环境（用模拟这个报错的 uv 测过，uv 的 Python 目录里有中文也行）。只用命令行的话，也可以先双击它一次
  建好 `.venv`。

## 自查

- `scripts/panel_hash.py`：升级代码前先跑一次，存下三块面板网格的哈希（`out/panel_hashes.json`，只在本机）；重建
  以后再跑一次，逐面逐色打印"相同 / 不同"，不打印哈希本身。打印姿态不受胶带厚度影响，按示例改了 `[mount]` 也
  不会让哈希变。
  - 这样比的是命令行构建的 `out/parts/print`。只用网页的话，升级前后各构建一次，直接比这两次任务（网页只留
    最近 5 次，旧的那次要还在）：
    `.venv/bin/python -I scripts/panel_hash.py out/web/<旧任务>/parts/print out/web/<新任务>/parts/print`。
- `scripts/wordmark_check.py`：重排「YU7 PRO」，和烘焙的轮廓逐位比对，防止字体库升级悄悄改了字形。
