# 挪车号码牌本机网页（webui）设计

**设计目标**：让用小米 XIAOMI LIFE 车载磁吸纸巾盒的车主，不手改 `config.toml`、不敲构建命令，也能做出自己的挪车牌。
- macOS、Windows、Linux 都能用（§6）。
- macOS、Windows 只有第一次准备时要用终端：装一次 uv，再 `git clone` 一次仓库（§3.1）；用 zip 下载的话，只有装 uv 这一条。Linux 还要在终端里装系统包、解开 AppImage，每次也在终端里启动（§3.1、§3.2）。
- 这套牌子只在作者的 YU7 上验证过，其他车型见 v3.4 稿 §7 第 5 条"适用车型"。

双击启动脚本（Linux 在终端里运行），浏览器里会打开一个只有这台电脑能访问的页面：
- **填写**：A、B 两面各填一个号码或一行自定义文字；L 面换成自己的车型字样，或者关掉 YU7 侧影只留一行大字。每个参数都有中文名、说明、范围、默认值和即时校验。
- **预览**：A、B、L 三面随输入实时显示，打不出来的字当场标出是第几个。
- **构建**：点「开始构建」，约 2.5–3.5 分钟。
- **出结果**：点「用 Bambu Studio 打开」直接打开 3MF 工程（两盘都在里面），通过"仅局域网"模式或 SD 卡打印。装配卡、报告和渲染图在页面里直接看。没装 Bambu Studio 时照样出检查、渲染、报告和装配卡，只是不出 3MF（§6.4）。

号码和文字只留在这台电脑上：页面只对本机开放，日志、报告和校验消息里都不会出现它们。

## 1 背景

你 10-19 的原话：

> 然后为了降低门槛，可以做一个 webui 进行所有调整和导出操作?

**现在的门槛**：
- 装 Python 环境；
- 手改 `config.toml`，键名和范围要对照 `config.example.toml` 的英文注释；
- 运行 `scripts/build_all.py`，到 `out/` 里找文件；
- 字打不出来时，要等构建开头报错，看终端里的英文消息。

**必须守住的**：
- **号码不出本机**：这条规则贯穿整个项目，网页不能破例。
- **构建离不开本机工具**：完整构建要用到 OCCT（build123d）、VTK（pyvista 渲染）和本机的 Bambu Studio。
  - 3MF 的完整工程设置，要用本机 Bambu Studio 自带的系统预设，加上本项目的覆盖值（99.4 % 收缩、冲刷量、擦料塔位置），由它的命令行合成。
  - 逐盘切片检查也靠命令行，其中包括"小件每层 ≥ 10 s"。
  - Mac 上一次完整构建约 200 s，峰值内存 1.2–1.4 GB。

## 2 方案比较

| 方案 | 好处 | 问题 | 结论 |
|---|---|---|---|
| **本机网页**（推荐） | 原样复用现有流水线（含 Bambu 命令行和渲染）；号码不出本机；不加依赖 | 仍要装 Python 环境（uv 一条命令）和 Bambu Studio（打印本来就要装） | 做 |
| 在线网页：浏览器里跑 build123d（Pyodide + OCP.wasm） | 免安装 | 1）浏览器起不了子进程，调不了 Bambu 命令行。3MF 只能附一份事先生成的静态工程设置，它从 Bambu 的 AGPL 预设派生，能不能放进 MIT 仓库待定；缺了工程设置的 3MF，按 Bambu Studio 最新源码（02.08.04.57）打开时只读几何，两盘、每件设置、冲刷量都会丢。2）没有 VTK，出不了渲染图。3）单线程：第三方实测热态约为原生的 1.6–1.8 倍，但那次原生也限成了单线程，和正常的原生构建比，估计慢 2–3 倍；冷启动约 22.5 s；本项目首次下载估计 60–100 MB（没实测）。4）OCP.wasm 只有一个维护者。5）MiSans 不能托管，要用户自己选字体文件 | 不做 |
| 托管服务器 | 免安装 | 号码要上传到服务器，违背"号码不出本机"；要养服务器 | 不做 |
| Gradio / Streamlit 等框架 | 写得快 | Gradio、Streamlit 默认开遥测；Streamlit、NiceGUI 默认监听所有网卡；Gradio 默认主题从 Google Fonts 拉字体；只算主包和最大的依赖，安装包就有 8–46 MB | 不用 |
| 打包成桌面 App | 真正双击即用 | 要把 Python、OCCT、VTK 一起打包；macOS 还要签名和公证；每个平台都要单独打包和测试 | 第一版不做 |

**为什么用标准库**：
- 页面只有一个用户，在本机跑，`ThreadingHTTPServer` 够用。
- Python 官方文档说它"不建议用于生产，只做了基本的安全检查"。所以这里不用 `SimpleHTTPRequestHandler`：接口只走固定路由，静态文件走白名单，其余安全检查都自己做（§5）。
- 不加依赖，就不多一条供应链，也不会被遥测。

## 3 用起来什么样

### 3.1 第一次准备（只做一次）
1. 装 Bambu Studio（打印本来就要装）。
   - macOS、Windows：用官网的安装包；
   - Linux：用官方的 AppImage（Ubuntu 22.04、24.04 各一版），先解开，再把 `TISSUEPLATE_BAMBU_STUDIO` 指到解出来的 `squashfs-root/AppRun`（§6.3）；
   - 没装也能用，只是不出 3MF（§6.4）。
2. 装 uv：官网一条命令；macOS 也可以用 Homebrew，Windows 也可以用 winget。这一步和第 3 步的 `git clone` 要在终端里做。
3. 下载仓库：推荐 `git clone`。
   - 没装过 Xcode 命令行工具的 Mac，第一次运行 git 会先弹窗要求安装；Windows 要先装 Git。
   - 用 zip 下载也行，见 §3.2 的安全提示。
   - Windows 上把仓库放在自己的用户目录下（文件权限，§6.5），路径尽量短（Windows 默认没开长路径支持）。
4. 从 MiSans 官网下载字体，把 `MiSans-Bold.ttf` 放进 `fonts/`。
   - 字体协议不允许仓库附带这个文件。
   - 页面会检测字体：没有就显示下载步骤，加「打开 fonts 文件夹」「重新检测」两个按钮。
   - 文件的 sha256 和作者用的不一样时，只给黄字提醒，不拦（v3.4 稿 §7 第 5 条）。
5. Linux 另装系统包（Debian / Ubuntu 的包名；桌面版一般已经有前两组）：
   - 构建：`libgl1`、`libx11-6`；
   - 离屏渲染：`libegl1`、`libgl1-mesa-dri`；
   - 切片（Ubuntu 24.04 版 AppImage）：`libwebkit2gtk-4.1-0`、`libgstreamer-plugins-base1.0-0`。这一组装上以后能不能切片，还没实测（§6.6）。
   - Bambu 只出了 Ubuntu 22.04、24.04 两版 AppImage。Ubuntu 20.04 没有 `libwebkit2gtk-4.1`，切不了片，只能走不切片模式。

### 3.2 每次使用
1. 启动：
   - macOS：双击仓库里的 `start-webui.command`；
   - Windows：双击 `start-webui.cmd`；
   - Linux：在终端里运行 `./start-webui.sh`。

   第一次运行会用 uv 建环境，要联网下载约 280–390 MiB 的依赖：实测 Windows 约 3 分钟、WSL 约 5 分钟，环境占 0.9–1.5 GB。以后几秒就能打开。

   用 zip 下载的，第一次运行可能被系统拦下（用 `git clone` 下载的没有这一步）：
   - macOS：到「系统设置 → 隐私与安全性」点「仍要打开」。macOS 15 起右键 → 打开已经不管用了。也可以在终端里对这一个文件执行 `xattr -d com.apple.quarantine start-webui.command`（这一步没实测）。
   - Windows：可能弹"安全警告"或 SmartScreen，确认是这个仓库里的文件后点"运行"；也可以解压前在 zip 的属性里勾选"解除锁定"（都没实测）。
2. 浏览器自动打开 `http://127.0.0.1:<端口>/#token=…`。打不开时（比如在 WSL 里），把终端里显示的这条链接复制到浏览器。
3. 点「从 config.toml 读取」（有这个文件时才可点），或者直接填写；看预览；点「开始构建」，约 2.5–3.5 分钟。
4. 点「用 Bambu Studio 打开」，然后只用下面两种方式打印：
   - 打印机切到「仅局域网（LAN only）」模式，再从 Bambu Studio 发送；
   - 导出到 SD 卡。

   打印机绑定账号、用默认的"自动 / 云"模式时，发送打印会先把文件传到拓竹云（默认保存 90 天），Bambu Handy 的打印记录里还会有带号码的缩略图（拓竹官方 wiki，附录 B）。不要上传到 MakerWorld。
5. 按 Ctrl+C、关掉终端窗口（Windows 上是那个命令行窗口），或者点页面上的「停止」，服务器都会停，正在跑的构建也会整组停掉（§4.4）。

**命令行照旧可用**：`.venv/bin/python -I -X utf8 -u scripts/webui.py`（Windows 是 `.venv\Scripts\python.exe`，参数相同）。
- 可选参数：`--port N`、`--keep 5`（保留几次构建）、`--no-browser`。
- `--example`：只用示例配置，从不读写 `config.toml`。截图、录屏和自动化测试都用它。
- 命令行构建 `scripts/build_all.py` 不变。

**填写和校验**：
- 每次输入，停 0.3 s 后校验，只重画有变化的那一面。
- 字段错误写在该字段下面。
- 整体错误写在顶部。前横梁布局放不下时写"这组 `[mount]`（`pad_t`、`delta_up`、`tab_bottom`）放不下"，提示用垫厚预设一次改三项，不再引你去改盒子实测值（v3.4 稿 §5.5）。
- 任何一面有硬性错误时，「开始构建」不能点。A、B 两面都填了自己的号码或文字，才能点。
- 打开页面时（点「从 config.toml 读取」之前），不管有没有 `config.toml`，A、B 都留空，示例号码只作淡色占位。

**三面**：
- A、B 选「号码」或「文字」。选了「文字」却填了 1 开头的 11 位数字时，提示改用「号码」，因为两种排法不一样。
- L 面的三种情况和 v3.4 稿 §6.3 一一对应，预览见 §4.3。有侧影又写了汉字时，黄字提示"中文建议选'只放文字'"（v3.4 稿 §6.4）。
- L 面「图案」选项旁边写"SU7 车主建议选'只放文字'"（v3.4 稿 §6.14 第 8 问）。

**安装的垫厚**：
- **三档预设**：
  - 1.2 mm 双面胶，即作者实装的那一套：`pad_t` 1.2、`delta_up` 2.45、`tab_bottom` −39.3；
  - 0.5 mm 硅胶条，即 v3.3 设计值：0.5、1.75、−40；
  - 自定义：放开这三个框。
- 两档旁边注明"这两档打出来的零件相同，只是装配卡和报告里写的胶厚不同"。
- 读入时三个值和哪一档完全相同就选哪档，否则选自定义。
- 自定义里只改了 `pad_t` 时，黄字"挂片长度和下孔会跟着变，`delta_up`、`tab_bottom` 要一起改"。
- 不提供"不贴胶"：盖磁点 9.0 时不贴胶建不出来（v3.3 的结论），要试就走自定义，会被校验拦下。

**几个键的说明**：中文名和说明原文放在 `webui/schema.py` 一处，测试保证每个配置键都有。
- **「配合」一组**：不做试件（你 10-19 定的），所以每个键都写明管哪个零件、装配卡哪一步会发现不合适、往哪边改、改了只重打哪一件，和 README 的对照表一致（v3.4 稿 §7 第 5 条）。比如：
  - `far_hex_af`：P 的六角，推不进 EF 就减 0.05，只重打 P；
  - `hex_socket_af`：EN 的六角孔，K 推不进就加 0.05，只重打 EN；
  - `far_hole`：远端轴颈在这个孔里转，要转得开（v3.4 起的含义）；转不开先铰孔，再加 0.05，只重打 C。
  - 组首写一句：盖片和 P 也可以直接在切片软件里缩放一点再打；C、K、EN 缩放会带歪别的配合面，要改键（v3.4 稿 §7 第 5 条）。
- **改了「配合」的键以后**：结果区提醒"只重打改过的那一件：在 Bambu Studio 里删掉同盘别的对象；小件要和陪打柱 Q 同盘打，Q 在盘 1，要重打的件在盘 2 时把 Q 复制过去"。
- `[box]` 组：同款盒子（铭牌 O636）不用改。
- **退役键**：读入或导入时，黄字提示"v3.4 起不用，保存时去掉"。提示由 `parse_config` 返回给页面，不往终端打印。

**构建和结果**：
- **进度**：每秒刷新一次，按 build_all 打出的固定阶段行显示（§4.4）。
- **结果**：主按钮是「用 Bambu Studio 打开」和「在访达中显示」，都不复制文件。Windows、Linux 上第二个按钮换成各自的名字（§6.5）。装配卡、报告、渲染图在页面里直接看。
- **下载**：下载和打包是次要操作，旁边写明"会在下载文件夹里多一份带号码的副本，用完删掉"。
- **停止**：顶栏的「停止」调 `/api/shutdown`，停掉服务器，正在跑的构建一起取消。

**和 `config.toml` 的关系**：
- 启动时**不自动读**。点「从 config.toml 读取」才读，免得共享屏幕或录演示时露出号码。
- 「保存」的规则：
  - 按 `config.example.toml` 的段和键序，把所有键写全，带中文注释。数值照填的写，不四舍五入。写全以后，以后默认值变了，你的零件也不会悄悄跟着变。
  - 三个退役键不写；A、B 每面只在 `[numbers]` 或 `[text]` 里写一处；L 面文字框空着就不写 `l`。
  - 读入或导入的文件里有不认识的段或键（三个退役键除外）时，「保存」不能点，页面用红字点名是哪个段、哪个键（名字里 ≥ 7 位的数字串照 §5.2 换成 •••），请你先在文件里改好再读。这样拼错的键不会在保存时被悄悄丢掉。
  - 文件的 sha256 和页面读入时一样才写。不一样就返回 409，提示"`config.toml` 在外面被改过，请先重新读取"。
  - 页面没读过 `config.toml`（直接填写，或者用了「导入…」），而这个文件已经存在时：保存前先确认"会用页面上的内容覆盖现有的 config.toml，原文件留在备份里"。确认后照常备份，再按服务器这时读到的 sha256 原子替换。
  - 先写同目录的 `config.toml.tmp-<随机>`（0600，能被 `config*.toml*` 忽略），再原子替换；启动时删掉残留的 `config.toml.tmp-*`。
  - 备份：
    - 第一次保存前的原文件另存为 `config.toml.orig.bak`，永远不覆盖；
    - 每次保存另存 `config.toml.<YYYY-MMDD-HHMMSS>.bak`，只留最近 5 份。
    - 这些文件都是 0600，都被 `config*.toml*` 忽略。
  - 号码或文字为空、或者就是示例号码时，保存前先确认。
  - 「恢复默认」不动号码和文字。
  - 原文件里你手写的注释会被模板注释替换。第一次保存前的原文件在 `.orig.bak`，之后每次保存前的版本在时间戳备份里（留最近 5 份）。
- 命令行和页面用的是同一份配置。

## 4 架构

### 4.1 组成

```
浏览器（index.html + app.js + style.css，CSP 见 §5.2）
   │ fetch；每个 /api/ 请求带 X-Plate-Token 头（令牌来自 URL 的 #token=…，读完就从地址栏抹掉，存在 sessionStorage）
   ▼
127.0.0.1:<随机端口>  webui.server（ThreadingHTTPServer：查 Host / Origin / Sec-Fetch-Site、令牌、固定路由）
   ├─ schema / validate / config 读写 ─→ webui.schema ─→ tissueplate.config（SCHEMA、parse_config、check_field）
   ├─ preview ───────────────────────→ webui.faces ─→ text_layout / free_text / logo_text（排版和检查，不建 3D）
   ├─ open（Bambu Studio / 文件夹）──→ webui.platform（按平台起 Bambu Studio、在文件管理器里显示，§6.5），只认产物清单里的路径
   └─ build / jobs / files ──────────→ webui.jobs ─→ 子进程 python -I -X utf8 -u scripts/build_all.py --config <任务>/config.toml --no-v31
                                                     环境：按平台的最小环境（§6.5）+ TISSUEPLATE_OUT_DIR=<任务>、OPENBLAS_NUM_THREADS=1、
                                                     临时目录=<任务>/.tmp，白名单透传 TISSUEPLATE_BAMBU_STUDIO / _PROFILES
                                                     macOS / Linux：umask 077、独立进程组；Windows：Job Object
                                                     （取消、退出时整组停掉，连 Bambu 命令行一起）
```

### 4.2 接口

除静态页以外，所有请求都要带令牌。POST 只收 JSON，最大 2 MB。所有 `/api/` 响应都不让浏览器缓存（`no-store`），因为预览和文件里有号码。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/`、`/app.js`、`/style.css` | 静态页（白名单；不含秘密，照样查 Host） |
| GET | `/api/status` | 找到的 Bambu Studio 和版本、字体在不在、sha256 对不对、是否在构建、有没有 `config.toml` |
| GET | `/api/schema` | 每个键的中文名、说明、类型、范围或选项、默认值、只读标记 |
| POST | `/api/validate` | 校验整份配置：逐字段的错误和提醒（脱敏，§5.2），退役键提示 |
| POST | `/api/preview` | 某一面的 SVG 和要点：字号、离图案多远、警告和错误的字位 |
| GET / POST | `/api/config` | 读 `config.toml`（带它的 sha256）/ 按 §3.3 的规则保存（`--example` 模式下两者都关） |
| POST | `/api/config/export`、`/api/config/import` | 导出 TOML / 导入 TOML（格式错只报行列，不回显内容） |
| POST | `/api/open` | `{任务, 产物}`：用 Bambu Studio 打开 3MF，或在文件管理器里显示；只认产物清单里的路径 |
| POST | `/api/fonts/reveal` | 在文件管理器里打开 `fonts/` |
| POST | `/api/build` | 开始构建，返回任务号。配置不合法或预览有硬性错误返回 422，正在构建返回 409 |
| GET | `/api/jobs`、`/api/jobs/<任务>?since=N` | 任务列表；进度和新增的日志行 |
| GET | `/api/jobs/<任务>/files`、`/file?path=`、`/zip?groups=` | 产物清单、单个下载、按组打包 |
| POST | `/api/jobs/<任务>/cancel`、`/delete` | 取消、删除整个任务目录 |
| POST | `/api/shutdown` | 停服务器（正在跑的构建一起取消） |

**原型里没有的接口**：`/api/config`、`/api/open`、`/api/fonts/reveal` 是这一版新加的，§5.4 的 31 项测试覆盖不到，§9 逐条补测试。

### 4.3 预览

预览只排版、只检查，不建 3D。它和构建调用同一套排版函数，读同一个字体文件。

| 面 | 做法 | 耗时 |
|---|---|---|
| 号码面 | `number_layout` 加 fontTools 轮廓。和 build123d 字形比，包围盒差 0.0000 mm（22 个字形实测） | 约 1 ms（网页原型实测） |
| 文字面（A、B） | v3.4 的 `free_text` 排版，加字怀、窄缝、断笔检查 | 排版和字怀 0.1–1.8 s（文字原型）；断笔另加每行 0.8–2.3 s（v3.4 稿 §6.9 的样例实测）。断笔结果按"字 + 字号 + 压缩"缓存，可以比排版晚一步显示 |
| L 面，有侧影，没填字 | 直接画 `geometry.json` 的环，不走新代码 | 第一次约 10 ms，之后走缓存（网页原型实测） |
| L 面，有侧影，填了字 | v3.4 的 `logo_text`：字号、离图案多远、位置、逐字结果 | 热态 0.7–1.2 s（L 面原型） |
| L 面，只放文字 | `free_text` 按 L 面排：字号、墨迹高、逐字结果；文字框空着时红字"只放文字时必须填" | 同文字面 |

**不在预览里查的**：v3.4 文字功能里的 CAD 修复和"切面后硬查"只在构建时跑（v3.4 稿 §6.8）。极少数字会在那里才报错，报错消息照样说明是第几个字。

**不用的**：
- `bd.ExportSVG`：build123d 0.13.0 导出字形面时会丢掉嵌套的位置，画出来的坐标是错的（原型实测）。
- "精确预览"按钮：用 build123d 建一遍，号码面约 1 s，L 面 14–18 s。快速预览已经够判断，第一版不做。

**冷启动**：服务器 0.1 s 就能打开页面。后台线程同时预热 build123d，约 2 s、约 400 MB 内存，用户基本感觉不到。

### 4.4 构建

**流程**：
1. 校验通过、预览没有硬性错误后，建任务目录 `out/web/<YYYY-MMDD-HHMMSS-xxxx>/`（0700），写入这次的 `config.toml`（0600）。
2. 起子进程 `build_all.py --config <任务>/config.toml --no-v31`。v3.1 对比是给开发者查回归用的，页面上不跑；命令行默认照跑。
3. build_all 每进入一步打一行固定格式的 `[stage i/7] <名字>`，页面据此显示进度。
4. 结束后按退出码显示结果，列出产物。

**7 个阶段**和实测用时（都是 `--no-v31`、退出码 0）。Mac 是网页原型的墙钟，合计 202.8 s；Windows 是命令行构建，BLAS 限 1 线程，按 build_all 自报合计 151 s（不含 import，墙钟 153 s），所以第 1 步的 6 s 也不含 import：

| 阶段 | 名字 | Mac | Windows |
|---|---|---|---|
| 1 | 读配置、建模（含 import） | 约 10 s | 6 s |
| 2 | 几何校验 | 44 s | 15 s |
| 3 | 导出 STL / STEP | 约 4 s | 约 6 s（合计减其余各步） |
| 4 | 检查 ①–⑩ | 102 s | 111 s |
| 5 | 出盘和 Bambu 命令行切片 | 37 s | 9 s |
| 6 | 渲染和装配卡 | 4 s | 4 s |
| 7 | 报告 | < 1 s | < 1 s |

- 现在的代码是在渲染那一步的最后写装配卡（`render.py`），所以第 6 步叫"渲染和装配卡"。
- 带自定义 L 面字时，第 1 步的"切面后硬查"要先做一遍 L 面三色网格，多出约 30–60 s（v3.4 稿 §6.8）；第 3、5 步的网格也会更长。
- 内存：构建子进程峰值 1.24 GB，服务器 0.4–0.5 GB。

**退出码**（build_all 统一，命令行也受益）：

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 检查或切片没过 |
| 2 | 配置错误（含打不出来的字） |
| 3 | 走了"不切片"模式：没找到或起不来 Bambu Studio，或者用了 `--no-slicer`（§6.4） |
| 4 | 未预期的内部错误：终端只打异常类型、出错位置（文件:行）和日志路径；完整 traceback 写进输出目录的 `build_error.log`（网页构建是任务目录，命令行是 `out/`） |

**其他规则**：
- **同一时间只跑一个**：再点「开始构建」返回 409。
- **取消和退出**：
  - 取消时整组进程一起停，状态写成"已取消"。
  - 服务器处理 Ctrl+C、关终端窗口（macOS / Linux 是 SIGHUP，Windows 是关闭控制台）和 SIGTERM：都先停掉整组构建进程再退出。
  - Windows 上"整组"靠 Job Object：服务器意外退出时，系统关掉句柄，构建和 Bambu 命令行也一起结束。各平台的做法见 §6.5。
  - 下次启动时，把上次留下的"运行中"任务标成"已中断"。
- **临时文件**：
  - Bambu 命令行的临时备份，由 v3.4 改过的 `bambu.py` 放进 `<任务>/.bambu_tmp`，每次跑完就删（v3.4 稿 §7 第 7 条）；
  - 构建子进程的临时目录（`TMPDIR`，Windows 另设 `TEMP`、`TMP`）另外指到 `<任务>/.tmp`，兜住其他程序的临时文件，删任务时一起删。
- **子进程环境**：
  - 只给按平台的最小环境（§6.5），外加白名单里的 `TISSUEPLATE_BAMBU_STUDIO`、`TISSUEPLATE_BAMBU_PROFILES`。服务器环境里的其他变量传不进去。
  - 命令行参数里也没有号码和令牌。

## 5 隐私和安全

### 5.1 防什么
- **你电脑上打开的其他网页**：恶意网站可以让浏览器往本机端口发请求，借机启动构建、读出配置。手段有跨站请求和 DNS 重绑定。
- **同一局域网的其他设备**：服务器只绑 127.0.0.1，它们连不上。
- **号码进日志、缓存、链接和云端**：
  - 终端日志、浏览器磁盘缓存、地址栏和历史；
  - 浏览器的云端拼写检查和写作助手扩展，会把输入框里的字发出去；
  - 自动填充。
- **不防**：
  - 以你的身份运行的恶意程序：它本来就能直接读 `config.toml` 和 `out/`；
  - 有全站权限的浏览器扩展：它能读这个页面。建议用没装扩展的窗口打开。

### 5.2 措施
- **监听**：只绑 127.0.0.1，端口随机。
- **令牌**：
  - 每次启动生成一个新令牌（256 bit），比较时用防计时攻击的函数。
  - 令牌只放在链接的 `#token=` 里，浏览器不会把 `#` 后面的部分发给服务器。这条链接会留在终端回滚、浏览器历史和打开浏览器时的进程参数里（§10 第 6 条）。
  - 页面读完令牌就从地址栏抹掉，存进 sessionStorage，关掉标签页就没了。
  - 每个 API 请求都用请求头带令牌。
- **来源检查**：
  - `Host` 必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`，防 DNS 重绑定；
  - 请求带了 `Origin` 时必须是本页；
  - `Sec-Fetch-Site` 只认 `same-origin`、`none`。例外（你 10-20 定的）：别的网页上的链接可以打开页面本身（`/`，整页跳转），页面里没有号码；接口和脚本照旧只认这两种。
- **跨站**：
  - 不发任何 `Access-Control-*` 头，预检请求直接 405；
  - POST 只收 JSON，表单和 text/plain 这类跨站能直接发的格式一律 415。
- **响应头**：
  - CSP 写全：`default-src 'self'; img-src 'self' blob:; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`。预览和渲染图要用 `blob:`。
  - 另加 `nosniff`、`no-referrer`、`X-Frame-Options: DENY`；页面里没有内联脚本。
- **输入框**：
  - 号码框、A / B 文字框和 L 面文字框一律加上 `spellcheck="false" autocomplete="off" autocorrect="off" autocapitalize="off" data-gramm="false"`，不用 `type="tel"`，不走表单提交。
  - 页面加 `<html translate="no">`。
  - 页面状态只放在内存里，不用 localStorage / IndexedDB。
- **日志和消息脱敏**：
  - 访问日志默认关；`--verbose` 也只打方法、路径和状态码。预览用 POST，号码不进 URL。
  - v3.4 起，`config.py` 的报错本身就不带填的值，只写段名、键名、类型和允许的范围；段名、键名里 ≥ 7 位的数字串也换成 •••（v3.4 稿 §8.1）。
  - 网页再兜底一层：把号码和所有文字的原值、去掉空格和"-"之后的写法，都换成 `•••`；数字之间夹着空格、横线、括号，合计 ≥ 7 位的，也换成 `•••`。构建日志在显示前同样处理。
- **下载和打开**：
  - 只认产物清单里的相对路径；
  - `..`、绝对路径、反斜杠、NUL、符号链接、清单外的文件一律拒绝；
  - 最后再确认实际路径还在任务目录里。
  - `/api/open` 只对清单里的 3MF 起 Bambu Studio，只对清单里的文件调"在文件管理器里显示"（各平台的做法见 §6.5）。

### 5.3 Bambu 命令行的临时备份（调研时发现，命令行流水线也有）

- **问题**：每次切片，Bambu Studio 命令行都会在用户临时目录的 `bamboo_model/<日期>/<时间#进程号#3>/` 留一个约 50 KB 的文件夹，不会自动删掉。临时目录在 macOS 上是 `$TMPDIR`，Windows 上是 `%TEMP%`；Linux 上按程序里的字符串推断是 `$TMPDIR`（没设时是 `/tmp`），没实测。
- **里面有什么**：只有工程设置 `_temp_3.config`（约 49 KB）、`lock.txt` 和记录 3MF 路径的 `origin.txt`，没有网格，所以没有号码。Windows 实测如此；你 Mac 上已有的 76 个也都只有这三个文件。我只看了文件名和大小，没打开。之前几稿写的"里面是带号码的网格"是错的。
- **为什么还要改**：每切一次多一个，越积越多；`origin.txt` 里有带用户名的本机路径。
- **图形界面**（10-20 在 Mac 上实测，再对照 02.08.02.61 源码 `bbs_3mf.cpp` 里的备份管理 `_BBS_Backup_Manager`）：

### 6.2 先修两处（三个平台的代码共用）

1. **文本编码**：
   - 5 处 `open()` 没写编码：4 处读写 JSON，1 处是 Bambu 的日志句柄。Windows 的默认代码页不是 UTF-8 时（简体中文版是 cp936，西文版是 cp1252），构建在几何校验写报告时就崩溃，只出几何也一样。
   - 你那台开了系统级 UTF-8，问题被盖住了；模拟 cp936、cp1252 时，都在 `verify_geometry.py` 写报告那一步崩溃。
   - 改法：4 处 JSON 加 `encoding="utf-8"`；Bambu 日志句柄改成二进制写；启动脚本和网页起子进程时一律用 `python -I -X utf8 -u`。`-I` 会忽略 `PYTHONUTF8` 这类环境变量，所以要写成参数。
2. **BLAS 线程**：
   - Windows 和 Linux 上，numpy、scipy 各带一份 OpenBLAS，默认各按 CPU 的逻辑核数开线程（你这台是 16）。检查 ⑩ 要反复解 770 阶、1540 阶的方程组，线程互相抢：
     - Linux：检查 ⑩ 544 s，限 1 线程以后 20 s；检查合计从 623 s 降到 96 s；
     - Windows：检查 ⑩ 从 64.8 s 降到 24.6 s。有一次照原样构建，9 分多钟还没跑完检查 ⑩；电脑另有负载时，单次求解能慢 275 倍。
   - 改法：`build_all.py` 在 import numpy 之前设 `OPENBLAS_NUM_THREADS=1`（已经设了就不动），网页的子进程环境也带上。macOS 的 numpy 用 Accelerate，应该不受影响，实施后在 Mac 上复测一次总时间。

另有几处小的：
- 报告、装配卡和渲染图标题里的路径，在 Windows 上会写成反斜杠，改成 `/`；Markdown 文件统一写 LF 换行。
- `concept/v3.1/verify_v3_1.py` 写死了作者 Mac 上的字体路径（v3.4 稿 §7 第 1 条已经要改）。WSL 实测：不改的话，作者那台 Mac 以外的机器（别人的 Mac 也一样）默认构建都报错。
- `build_plate0b.py` 调了 `date` 命令，Windows 上没有，改用 Python 取时间（看代码发现的，没运行）。

### 6.3 找 Bambu Studio

1. 先看环境变量 `TISSUEPLATE_BAMBU_STUDIO`（可执行文件）和 `TISSUEPLATE_BAMBU_PROFILES`（profiles 目录）。设了但路径不存在时，按"没找到"处理，不再往下找（§9 第 6 条靠这一条测不切片模式）。
2. 再按平台找默认位置：

   | 平台 | 可执行文件 | profiles | 版本从哪读 | 状态 |
   |---|---|---|---|---|
   | macOS | `/Applications/BambuStudio.app`、`~/Applications/BambuStudio.app` 里的 `Contents/MacOS/BambuStudio` | `Contents/Resources/profiles/BBL` | `Info.plist` | `/Applications` 是现在的做法；`~/Applications` 和读 `Info.plist` 是新加的 |
   | Windows | `%ProgramFiles%\Bambu Studio\bambu-studio.exe` | `resources\profiles\BBL` | exe 的文件版本（产品版本那一栏是空的） | 实测 |
   | Linux | 没有默认位置，用环境变量指到解开的官方 AppImage：`<目录>/squashfs-root/AppRun` | `squashfs-root/resources/profiles/BBL`（不用另设） | 读不到就不比 | 路径实测对；命令行要两个系统包（§3.1），没测 |

3. 找到以后先试跑一次。起不来时（比如 Linux 缺系统库，退出码 127）也算用不了：走不切片模式，并说明是缺了哪个库。

- **Linux 的 AppImage 要先解开**：profiles 在 AppImage 里面，不解开读不到。解开不需要 FUSE，实测 0.75 s。README 写 `./BambuStudio_ubuntu24.04-*.AppImage --appimage-extract`，再把环境变量指到解出来的 `squashfs-root/AppRun`。
- **不专门支持**：Flatpak（沙箱里还要另给 `out/` 的读写权限）、发行版自己打的包。都可以用环境变量指过去，没测。
- **版本不一样时**：现在的三个预设名和 3MF 版本号，都按你本机装的 02.08.02.61 写，Windows 上是同一个版本。检测到别的版本时，页面给黄字提醒；预设文件找不到时，直接说清楚是哪个文件没找到。
- **Windows 上的命令行诊断**：`bambu-studio.exe` 不往重定向的输出里写日志（三份日志都是 0 字节），出错时只能看输出目录里的 `result.json`。所以每次调用都带 `--outputdir`，不带的话它会在当前目录写一个 `result.json`；失败时把 `result.json` 里的错误说明报出来。

### 6.4 没装或用不了 Bambu Studio：不切片模式（你 10-19 选的）

- **现在**：没装时，构建在出盘这一步报 `FileNotFoundError`；装了但起不来时（WSL 实测）报 `RuntimeError`（code 127）。都是退出码 1，没有渲染、装配卡，也没有报告。
- **改成**：没找到或起不来时自动走这个模式；命令行也可以用 `--no-slicer` 指定。约 +60 行。
  - 照常跑检查 ①–⑩、渲染、报告和装配卡，只跳过出 3MF 和切片检查。出 3MF 之前读预设、导出工程设置这两步也要用 Bambu，一起跳过。
  - 报告里的切片检查（⑪）写"未切片"，退出码 3。
  - 装配卡列出每件要在切片软件里手动设的项：墙数、填充、brim、Q 的 20 mm/s、小件每层 ≥ 10 s 的打法、AMS 槽，以及要选的三个预设。
  - WSL 实测：跳过这几步以后，检查、渲染、报告和装配卡都正常，共 125 s。
- **为什么不出"不带工程设置的 3MF"**：按 Bambu Studio 最新源码（02.08.04.57），3MF 缺少工程设置时只读几何，两盘、每件设置和冲刷量都会丢，等于在 GUI 里从头重做。只写一部分设置也不行，缺的键会回落到程序内置默认值，不是系统预设。
- **没选的做法**：只开放"只出 STL / STEP"，即现在的 `--geometry-only`。不跑检查 ①–⑩，也没有装配卡、报告、渲染图和每件打印设置，只适合会自己切片的人。

### 6.5 各平台的差异，网页和构建怎么处理

| 项 | macOS | Windows | Linux |
|---|---|---|---|
| 启动脚本 | 双击 `start-webui.command` | 双击 `start-webui.cmd`。只用 ASCII、CRLF 换行。不用 `.ps1`：双击 `.ps1` 默认用记事本打开，还受执行策略限制 | 终端里运行 `./start-webui.sh`（LF 换行，可执行） |
| 建环境 | `uv venv --python 3.12`，再 `uv pip install` | 同左。`uv venv` 报 os error 448（uv 管理的 Python 用了目录联接，这台机器不信任这类装入点）时，改用那个 Python 的真实路径跑 `-m venv`，再 `uv pip install`，实测可行 | 同 macOS。不用系统自带的 python3 |
| 用 Bambu Studio 打开 | `open -a` | 直接起 `bambu-studio.exe <3MF>`，因为 `.3mf` 不一定关联到 Bambu Studio | 直接起 `AppRun <3MF>`（没测） |
| 在文件夹里显示 | `open -R`，按钮叫「在访达中显示」 | `explorer /select,<文件>`，按钮叫「在资源管理器中显示」。它成功时也返回 1，不能按返回值判断 | 有桌面时 `xdg-open <目录>`，WSL 里用 `explorer.exe`，都没有就只显示路径。按钮叫「打开所在文件夹」 |
| 打开浏览器 | `webbrowser` | `webbrowser`，实测能用 | 有桌面时 `webbrowser`；打不开时（比如 WSL）提示复制终端里的链接（没测） |
| 取消、退出 | 构建放在独立进程组里，整组停。处理 Ctrl+C、SIGHUP（关终端窗口）、SIGTERM | 构建放进一个 Job Object，服务器退出、句柄关掉时整组结束；取消时结束整个 Job。实测：只停 python 的话，`bambu-studio.exe` 会接着切片；`taskkill /T /F` 能停整棵进程树。处理 Ctrl+C 和关闭窗口。取消后删掉残留的 `*.gcode.tmp` | 同 macOS |
| 子进程环境 | `PATH`、`HOME`、`LANG` | 至少要 `PATH`（含 System32）、`SystemRoot`、`USERPROFILE`、`TEMP`、`TMP`，再加 `APPDATA`、`LOCALAPPDATA`。实测缺 `SystemRoot` 直接崩溃，缺 `USERPROFILE` 报"找不到用户目录" | 同 macOS，另加 `DISPLAY`、`WAYLAND_DISPLAY`、`XDG_RUNTIME_DIR` |
| 文件权限 | 0600 / 0700 | `chmod`、`umask` 不起作用（实测 0600 建出来是 0666），靠用户目录继承下来的权限：只有本人、SYSTEM 和管理员能读。仓库不在自己的用户目录下时，页面黄字提醒 | 同 macOS |
| 渲染 | 现在的做法 | 有显卡时 SSH 会话里也能硬件加速。没有 OpenGL 3.2 的机器（虚拟机、部分远程桌面）上渲染会失败：跳过渲染，报告和页面写明"这台电脑没出渲染图"，其余照常 | 没有显示时自动走 EGL，不用改。不要强制 OSMesa：没装这个库时直接段错误 |
| 内存显示 | `resource` 模块 | 没有 `resource` 模块，原型的服务器在这里根本起不来。改用系统调用读，读不到就不显示 | 同 macOS |

三个平台都给构建子进程加 `OPENBLAS_NUM_THREADS=1`、`TISSUEPLATE_OUT_DIR`，并把临时目录指到任务目录：`TMPDIR`，Windows 另设 `TEMP`、`TMP`（§5.3）。

**用户目录里的缓存**：matplotlib、ezdxf 第一次运行时会在用户目录建字体缓存（Linux 上还有 Mesa 的着色器缓存），里面没有号码。README 的常见问题里说明一下，不另外处理。

## 10 风险

1. **浏览器兼容**：CSP、blob 显示、sessionStorage 令牌这几样，只在 Chrome 自动化里测，Safari 靠你手点。
2. **Bambu Studio 升级**：预设名或 3MF 版本串可能变，profiles 文件就会找不到。有提醒，但要跟着改代码。
3. **三个平台的差异多**：编码、BLAS 线程、进程树、权限、Bambu 的位置都不一样（§6.5）。Windows 原生和 WSL 实测过；真桌面、cp936 的真机器、没有显卡的机器、其他发行版都没测（§6.6）。
4. **系统的安全提示**：zip 下载的启动脚本第一次会被拦（macOS 的 Gatekeeper、Windows 的安全警告或 SmartScreen），新手可能卡在这一步。README 推荐用 `git clone`。
5. **进度靠固定阶段行**：build_all 的阶段名改了，页面要跟着改，有测试守着（§9 第 8 条）。
6. **令牌会留在几个地方**：终端回滚、浏览器历史里第一次打开的那条链接、打开浏览器那一瞬间的进程参数（同机其他用户能看到）。好在令牌每次启动都换，任务目录是 0700，风险低。
7. **浏览器把输入发到云端**：拼写检查、写作助手、自动填充同步。输入框属性能挡住常见的几种，挡不住所有扩展。
8. **自动保留会删掉旧任务**：页面上写明规则，数量可以调。留 5 次约占 0.4 GB。
9. **内存**：构建峰值 1.2–1.4 GB，8 GB 内存的机器也够，只是同时开别的大程序会慢。
10. **"保存到 config.toml"会丢掉手写注释**：第一次保存前的原文件留在 `.orig.bak`，之后每次保存前的版本在时间戳备份里（留最近 5 份）。
11. **第一次建环境要联网**：下载 280–390 MiB 的依赖，环境占 0.9–1.5 GB；网络不好时会慢，一次装好以后就不用了。
12. **Linux 切片靠两个系统包**：不同发行版的包名不一样，装不上就只能走不切片模式。
13. **uv 在部分 Windows 上建不了 3.12 的环境**（os error 448）：启动脚本有退路，但退路只在你这一台上试过。
14. **Windows 的文件权限靠用户目录**：仓库放在别处（比如 D 盘根目录）时，同机的其他用户可能读到 `config.toml` 和 `out/`。页面会提醒。
